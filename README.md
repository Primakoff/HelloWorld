## 2. Как, скорее всего, украли: разбор вектора атаки

Это главный урок дела. Есть два принципиально разных способа кражи, и их можно отличить
по блокчейну:

| Признак | Утёк ключ / seed | Подписал вредоносное (approve / permit) |
|---|---|---|
| Кто отправитель кражи | **Ваш адрес** (транзакция подписана вашим ключом, растёт ваш nonce) | Чужой адрес вызывает `transferFrom` |
| Нативная монета (ETH, BNB) | Уходит | **Не может** уйти через approve |
| Сколько сетей | Все сети сразу | Только там, где подписали |
| Несколько кошельков | Все, у которых тот же seed / тот же телефон | Только тот, которым подписали |

**В моём случае:** украли с двух кошельков, в том числе SafePal, seed которого я
**вводил в телефон как мнемонику**. Это почти наверняка **компрометация seed-фразы**,
а не approve.

> Ключевая ошибка: холодный кошелёк защищает только пока seed никогда не касался
> устройства с интернетом. Ввод мнемоники в телефон превратил холодный кошелёк в горячий.
> С этого момента безопасность всех средств = безопасность телефона.

Возможные пути утечки (проверить каждый):
- [ ] seed записан в заметки, на скриншот, в фото или облако (iCloud/Google Photos/Drive)
- [ ] приложение кошелька скачано не из официального источника (поддельный SafePal/MetaMask)
- [ ] seed вводился на сайте («проверка кошелька», «синхронизация», «claim airdrop», «support»)
- [ ] seed копировался через буфер обмена (вредоносные приложения его читают)
- [ ] на телефоне есть подозрительные приложения или профили (VPN, «бусты», клавиатуры)
- [ ] тот же seed импортирован в несколько кошельков или расширений браузера

**Что проверить в блокчейне:** открыть транзакцию кражи на Etherscan / Optimistic Etherscan.
Если в поле `From` мой адрес, ключ украден. Время первой кражи сравнить
с тем, что я делал в тот день (сайты, приложения, сообщения).

## 3. Срочная гигиена (до любых аирдропов)

1. **Скомпрометированный кошелёк = кошелёк хакера.** На такие адреса обычно ставят
   sweeper-бота, который за секунды забирает всё, что приходит. **Ничего туда не отправлять:**
   ни газ, ни для клейма аирдропа.
2. Аирдроп (например, награды Jumper) на скомпрометированный адрес можно попытаться
   спасти только **атомарным бандлом через Flashbots**: оплата газа, клейм и перевод
   на чистый адрес идут в одном блоке, и бот не успевает вмешаться. Это делается своим
   кодом или с человеком, которому вы доверяете. «Сервисы спасения», которые просят
   seed, — это следующая кража.
3. Новый кошелёк: **новый seed**, созданный на устройстве, а не импортированный.
   Seed только на бумаге или металле, никогда в телефоне.
4. Остаток ($200) держать на новом кошельке. Не путать адреса старого и нового.
5. Телефон: удалить лишние приложения, сменить пароли почты и бирж, включить 2FA
   через приложение (не SMS). При серьёзных подозрениях — сброс до заводских настроек.
6. Перевод на Robinhood: связь между адресом и аккаунтом с KYC появится в любом
   случае, но это **ваш** кошелёк и ваш KYC, в этом нет ничего опасного.

## 4. Методика расследования (чек-лист)

- [ ] **Шаг 0. Мои адреса.** Вписать в `case/addresses.csv` свои адреса и хэши краж.
- [ ] **Шаг 1. Моя кража.** Найти транзакции, где мои активы пришли на 0xF889…
      (или на промежуточный адрес). Определить вектор (раздел 2).
- [ ] **Шаг 2. Выгрузка.** Arkham → Transfers → значок сохранения (CSV), отдельно
      INFLOW и OUTFLOW, все страницы. Или `fetch_etherscan.py`.
- [ ] **Шаг 3. Отчёт.**
      `python3 tracer/analyze.py --target 0xF8895A77af3AD64c56d433DC0Ad0fD8D7D2704bF exports/*.csv --out case/report.md`
- [ ] **Шаг 4. Финансирование.** Кто первым прислал газ на 0xF889…? Идти по этой
      цепочке назад, пока не дойдёте до биржи, моста или миксера (Tornado).
- [ ] **Шаг 5. Кластер.** Адреса с ⇄ и газовые доноры → проверить → добавить как `--target`.
      Перезапустить анализ уже по кластеру.
- [ ] **Шаг 6. Следующие хопы.** `next_hops.csv`: по каждому крупному получателю
      (61K USDT, 45K USDC, 26K USDT) — снова шаги 2–5.
- [ ] **Шаг 7. Точки выхода.** Все депозиты на биржи с KYC (KuCoin!) — хэш, сумма, время.
      Это материал для заявления в IC3.

### Эвристики кластеризации (как аналитики связывают адреса)

| Эвристика | Сила |
|---|---|
| Адрес A оплатил газ адресу B | Сильная |
| Деньги ходят туда-обратно между A и B | Сильная |
| Один депозитный адрес биржи у A и B (биржа сводит депозиты в один аккаунт) | Очень сильная |
| Одинаковые суммы и время с разницей в минуты | Средняя |
| Одинаковые паттерны газа (gas price, nonce-ритм), один и тот же софт | Слабая–средняя |
| ENS-имена, NFT, взаимодействие с одними и теми же «личными» контрактами | Средняя |

## 5. Учебный план

**Уровень 1 — чтение блокчейна (1–2 недели)**
- Что такое адрес, транзакция, nonce, gas, блок. Чем нативный перевод отличается от ERC-20 `Transfer`.
- Etherscan: вкладки Transactions / Internal / Token Transfers, Input Data, Logs.
- Практика: разобрать по полям 5 транзакций из этого дела.

**Уровень 2 — механика краж (2–3 недели)**
- `approve`, `permit` / `permit2`, `setApprovalForAll`; как работают дрейнеры.
- Sweeper-боты и мемпул; что такое Flashbots и приватные бандлы.
- Как выглядят фишинговые подписи (EIP-712) и как читать их перед подписанием.
- Практика: [revoke.cash](https://revoke.cash) — проверить разрешения нового кошелька;
  разобрать один известный публичный кейс дрейнера.

**Уровень 3 — ончейн-расследование (1–2 месяца)**
- Инструменты: Arkham (Visualizer / Tracer), Breadcrumbs, MetaSleuth, Etherscan, DeBank, Dune.
- Следование через мосты (Stargate, Across, Relay) и обменники (ChangeNOW, FixedFloat).
- Практика: этот кейс, шаги 0–7. Писать выводы в разделы 1–2.
- Чтение: расследования ZachXBT, отчёты SlowMist / Chainalysis / Elliptic, MistTrack.

**Уровень 4 — автоматизация (по желанию)**
- Python + Etherscan API (смотри `tracer/`), граф в `networkx`, SQL-запросы в Dune.
- Задачи: дописать в `analyze.py` автоматический обход хопов на N шагов,
  поиск общего депозитного адреса бирж.

## 6. Правила дела

- Никаких «сервисов возврата», которые сами пишут вам. Никакого ввода seed куда-либо.
- Не писать хакеру и не угрожать ему: это ничего не даёт и раскрывает, что вы следите.
- Каждое утверждение = ссылка на транзакцию. Гипотеза ≠ факт: в `addresses.csv` есть колонка `status`.
- Адреса копировать, а не перепечатывать со скриншота (один адрес в реестре уже считан неполностью).
